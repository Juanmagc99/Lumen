# Agent-assisted development

The repository should show how decisions are made and changes are reviewed, not merely list AI tools.

1. Explore the problem and existing context.
2. For substantial changes, use OpenSpec to describe the proposal, scenarios, design and tasks, then review the decisions.
3. Implement in small increments using repository instructions and acceptance criteria.
4. Review the diff and report checks actually performed. Do not create, modify or run tests unless explicitly requested; do not add test-running CI jobs without that request.
5. Keep specifications and documentation aligned with actual behavior and report limitations honestly.
6. Close or archive changes according to the OpenSpec workflow.

AGENTS.md contains stable instructions; specifications describe behavior; architecture documents record decisions. The Impeccable plugin is available and can support the SPA's visual direction and review when frontend work begins.

Add project-specific skills when a repeated process warrants them. Future candidates include AI evaluation and reviewing a change against its spec. Any test or evaluation execution is subject to user direction. Select MCPs and plugins for concrete needs and review their permissions.

Preserve specifications, decisions and reviewable changes as portfolio evidence. Distinguish implementation from proposals and measured results from goals. Do not publish private conversations, third-party data or secrets.
